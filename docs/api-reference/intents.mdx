---
title: Intents
description: REST API endpoints for submitting, querying, and cancelling intents
---

All endpoints require the `X-API-KEY` header. Responses are JSON.

---

## Submit an intent

```http
POST /v1/intents
```

Submits a new encrypted intent to the gateway. The intent must be encrypted client-side using the gateway's public key before being sent.

**Request body:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `intent_id` | string | ✓ | Unique ID generated by `IntentBuilder` |
| `user_address` | string | ✓ | Starknet address of the user |
| `ciphertext` | string | ✓ | Hex-encoded AES-GCM encrypted intent payload |
| `encrypted_session_key` | string | ✓ | Session key encrypted with the gateway's X25519 public key |
| `client_public_key` | string | ✓ | Client's X25519 ephemeral public key (hex) |
| `commitment` | string | ✓ | Pedersen hash of the full intent — what goes on-chain |
| `user_signature` | string[] | ✓ | Starknet signature components from the user's wallet |
| `nonce` | string | ✓ | Random nonce used in intent hash and amount commitment |
| `authorization_hash` | string | | Optional: hash the user explicitly authorised off-chain |
| `submission_mode` | string | | `'GATEWAY'` (default) or `'SELF_COMMIT'` |

**Response:**

```json
{
  "intent_id": "0x...",
  "batch_id": "0x...",
  "estimated_execution_time": 28,
  "awaiting_user_transaction": true
}
```

`awaiting_user_transaction: true` means the gateway is waiting for your wallet to send the on-chain commitment transaction. Call `POST /v1/intents/:intentId/onchain` once the transaction confirms.

## List intents

```http
GET /v1/intents
```

Returns a paginated list of intents, optionally filtered.

**Query parameters:**

| Param | Type | Description |
|-------|------|-------------|
| `user_address` | string | Filter to a specific wallet address |
| `status` | string | `pending \| committed \| in_batch \| settled \| failed \| cancelled \| expired` |
| `batch_id` | string | Filter to intents in a specific batch |
| `limit` | number | Max results per page. Default `20`, max `100` |
| `offset` | number | Pagination offset |

**Response:**

```json
{
  "intents": [
    {
      "intent_id": "0x...",
      "user_address": "0x...",
      "status": "settled",
      "batch_id": "0x...",
      "created_at": "2024-01-01T00:00:00Z",
      "settled_at": "2024-01-01T00:01:00Z"
    }
  ],
  "total": 42,
  "limit": 20,
  "offset": 0
}
```

## Get a single intent

```http
GET /v1/intents/:intentId
```

Returns the current status and metadata for a single intent.

**Response:**

```json
{
  "intent_id": "0x...",
  "user_address": "0x...",
  "status": "settled",
  "batch_id": "0x...",
  "created_at": "2024-01-01T00:00:00Z",
  "committed_at": "2024-01-01T00:00:05Z",
  "settled_at": "2024-01-01T00:01:00Z",
  "failure_reason": null
}
```

## Cancel an intent

```http
POST /v1/intents/:intentId/cancel
```

Cancels an intent. Only valid while status is `pending` or `committed` and no auction has started for the intent's batch.

**Request body:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `user_address` | string | ✓ | Must match the intent's registered address |
| `user_signature` | string[] | ✓ | Starknet signature over the cancellation message |

---

## Notify on-chain confirmation

```http
POST /v1/intents/:intentId/onchain
```

Tells the gateway that the wallet's on-chain commitment transaction confirmed. The gateway will verify the transaction on Starknet and update the intent status from `pending` to `committed`.

**Request body:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `action` | string | ✓ | `'COMMITTED'` |
| `user_address` | string | ✓ | The intent owner's address |
| `tx_hash` | string | ✓ | The Starknet transaction hash of the commitment tx |
